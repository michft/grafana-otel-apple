## Apple Containers-specific findings

These are the main runtime constraints currently baked into the repo:

1. Single-file bind mounts were not reliable for this workflow.
   Use directory mounts like:
   - `--mount type=bind,source=${ROOT_DIR}/configs/rendered,target=/rendered,readonly`
   - Local repro on Apple `container` `0.12.3`:
     - host file source failed with
       `Error: path '/tmp/.../test.txt' is not a directory`
     - mounting the containing directory worked

2. Fresh Apple named volumes caused permission failures for default non-root image users.
   Current workaround:
   - Prometheus runs as `0:0`
   - Loki runs as `0:0`
   - Tempo runs as `0:0`
   - Pyroscope runs as `0:0`
   - Grafana runs as `0:0`

3. Container-name DNS was not treated as reliable in this flow.
   The repo renders backend IPs into runtime config instead.
   - Local repro on Apple `container` `0.12.3`:
     - a client container on the same custom network failed to resolve
       `http://<peer-name>:8080` with
       `wget: bad address 'otel-dns-test-srv:8080'`
     - direct IP access to the same peer worked

4. `container inspect` returns `[]` with exit code `0` for missing containers.
   The scripts rely on that behavior.
