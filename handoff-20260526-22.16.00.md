- `scripts/pyroscope-up.sh` works.
- `curl http://127.0.0.1:4040/ready` returned `ready`.

  - run as `0:0`
  - mount the rendered config directory, not a single file
- Pyroscope readiness is slow on this machine. One measured run took about 92 seconds from process start to `/ready` returning `200 OK`.

### OpenTelemetry Collector

- `scripts/otelcol-up.sh` works.
- `curl http://127.0.0.1:13133/ready` returned success.
- Current working Apple Containers pattern:
  - publish `4317`, `4318`, and `13133`
  - mount the rendered config directory, not a single file
  - point the collector to `/rendered/otelcol-config.yaml`
- The collector starts quickly on this machine once the image is present.
- Current startup logs include a non-fatal deprecation warning for the `otlp` exporter alias used by the profiles exporter.

### Grafana

- `scripts/grafana-up.sh` works.
- `curl http://127.0.0.1:3000/api/health` returned success.
- Grafana required the same Apple Containers directory-mount adjustment, but at the provisioning-tree level:
  - render a full `configs/rendered/grafana-provisioning/` tree
  - mount that directory to `/etc/grafana/provisioning`
- Grafana also runs as `0:0` to avoid fresh-volume permission issues.
- Datasource provisioning was verified through the Grafana API for Prometheus, Loki, Tempo, and Pyroscope.

## Apple Containers quirks already discovered

These were the main findings and are already reflected in code/docs:

1. Single-file bind mounts were not working for this flow.
   Use directory mounts like:
   - `--mount type=bind,source=${ROOT_DIR}/configs/rendered,target=/rendered,readonly`
   Then point the service to `/rendered/<config>.yaml`.

2. Fresh Apple named volumes caused permission issues with default non-root image users.
   Current workaround:
   - Prometheus runs as `0:0`
   - Loki runs as `0:0`
   - Tempo runs as `0:0`
   - Pyroscope runs as `0:0`
   - Grafana runs as `0:0`

3. Apple custom-network IP connectivity worked.
   Container-name DNS did not work in the early Alpine test, so the repo currently renders backend IPs into config files.

4. Apple `container inspect` returns `[]` with exit code `0` for missing containers.
   Scripts already handle that.
